# Visuals — self-contained explainers (HTML/SVG, corpus visual language)

Each file opens in a browser with no build step and no external asset. Published as
private artifacts in Swaroop's gallery; the URLs are the shareable form, these files are
the source. Built in the corpus visual language (`../visual-language/`): purple edges,
blue spine, green sends, teal storage, amber external, red refusals.

| File | What it is | Artifact |
|---|---|---|
| `playbook.html` | **Design brief.** One agent for every lender and every stage: the plan's `playbook` (a `lines` library + `blocks` chosen by the where-grammar) picks and fills the hook, the walk and the lender notes from the event, and hands the agent finished text — the agent never chooses. Kid version first, then the three-way comparison (vendor's schema · transformer node · playbook), why it is not only for voice (a block is a fact every node reads), the fire-time trace, the six laws, and the build order. Companion to `modules/05-outreach.md` §Playbook. | `claude.ai/code/artifact/e9017a62-5578-467a-8ca9-47b9b1dd27ab` |
| `run-history.html` | **Design brief.** Why a run knows where it is and never where it has been: one claimed visit walks four squares and writes one row, and the branch answers are deleted before that write. Traces the five losses to their lines, names what already survives (the manifest's `dedupe_key` carries the node id), and specifies `crm_workflow_step` (T26, migration 073) — append-only, flushed inside the move's own CAS, never read by the walker. Carries the full write-site matrix and three traps. Companion to `modules/05-outreach.md`. | `claude.ai/code/artifact/558b7a16-aa5c-4ed7-b70d-907710d6cdf5` |
| `buddy-stages.html` | **CURRENT.** The three-stage traffic plan with a live throughput dial: drag it and the pod ledger, the verdict and each stage's capacity bar recompute; overload a stage and a backlog stacks at the component that chokes.
