One actor, one playbook

One agent for every lender and every stage. The words it says — the opening line, the twelve-step walk, the lender's notes — are chosen by the workflow from what the event said, filled in, and handed over finished. The agent never picks. The agent template is only ever edited to change how the agent behaves.

Some holes are easy — the product name comes straight from the event, and that works today. The hard holes are choices: which opening line, which walk, whose notes. The choice depends on the lender, the stage she stopped at, and whether the offer is no-cost. None of that is in the event; it has to be decided from the event.

The playbook is where that decision is written down. When it's time to call, the walker reads the playbook, picks the right words, fills the little holes inside them, and hands the actor a finished page. The actor reads. It never decides.

And the fourth idea, dismissed on the way

One agent template per lender. It puts the words where prompt engineering lives, which is tempting. But the core agent — turn-taking, the ending rule, the tie-break — gets copied five times, and a fix to any of it is five edits. The constraint that decides it: one agent, edited only to change how it behaves. Words are not behaviour.

03

Why it isn't only for voice

A block is never sent to the agent. It becomes a fact on the run. Every node type already reads facts through one function, run_facts. Nothing else has to learn the playbook exists.

NodeHow it uses a blockChange to the node
call voice or chat agent the lead payload is run_facts, so {hook_line} and {walk} land in the prompt like any variable none
send WhatsApp "variables": { "1": "hook_line" } — the existing blank→fact map none
action webhook / connector "args": { "message": "{hook_line}" } — args already resolve {fact} none
email, SMS, anything later reads facts none
The one limit, already enforced

A WhatsApp template parameter may carry no line break — a law the send node already has. So a multi-line block like walk can go to a call or a webhook, and publish refuses it if mapped to a WhatsApp blank. A single-line block like hook_line goes anywhere. Same playbook: the voice agent gets the walk, the WhatsApp nudge gets the hook, the webhook gets the notes.

rule 1

Every piece of text lives in lines, once

A block never contains a sentence — it names one. Reword step_open_app and every walk that uses it changes. Add a lender: its lines, then one when row per block.

rule 2

say is a name, or an ordered list of names

One name renders as that line's text. A list renders as - name: "text", one per line, in order — the ORDER and LINES sections of the prompt, generated. First when that holds wins; the last entry has no when.

Nothing here is new vocabulary. when is the where-grammar over the condition square's field grammar (context.*, facts.<node>.*, customer.*). First-match-wins with a mandatory default is the condition square's else. A line with {holes} is the send node's blank law. The only new words are playbook, lines, blocks and say.

Why we fill the small holes on our side, and never leave it to the agent

The template loader's substitution is one pass: text.replace("{key}", value) looping over the variables dict (template/utils.py:24). There is no second pass. A hook_line that still contains {product_name} gets that inner hole filled only if product_name happens to sit later in the dict — which depends on the order of expected_payload_schema. It would work in testing and break when someone reorders a field, and the failure is the agent saying "आपने {product_name} के लिए" aloud on a live call.

So the playbook renders every hole before the text leaves. The agent's single pass has nothing left to guess.

06

The laws

publish

Every block ends in a default

The last entry has no when, or publish refuses. It's the condition square's else, and it's what guarantees the agent never speaks a literal {hook_line}.

publish

Every name in say exists in lines

A typo is a 422 at publish, never a blank page on a call.

publish

Every {hole} is a declared fact

The same right-hand-side law the send node's variables already has: a catalog variable for the plan's topics, or a run fact.

publish

Every when field is one the grammar accepts

Reuse predicates.field_problems. A block reads what a condition square can read, nothing more.

publish

A single-line block only, into a WhatsApp blank

The existing newline law. walk to a call is fine; walk mapped to a WhatsApp parameter is refused.

fire time

A leftover {hole} parks the run

With the hole named in last_error, readable on the merchant's screen. The agent will not catch it, so we must.

Two more, so it stays simple

A line fills from facts only, never from another line. No chains, no cycles, always total.

Blocks render into the payload, never into the run context. Context scalars are capped (CRM_CONTEXT_VALUE_MAX_CHARS) and canon says the row stays small. The name of the chosen row can be recorded — hook_<node>, beside split_<node> — for the funnel; the text never is.

08

Why it suffices — and what it deliberately leaves alone

Steps already done

The prompt already reads pending={pending_steps} from the event and says "never re-walk anything the profile shows as done." So start with one walk per lender. If trimming on our side ever proves necessary, that's more when rows keyed on loan_state — no code change.

UPI versus bank, mid-call

Stays with the LLM. The [UPI autopay only — skip] annotations on the lines already do this, and it's a decision made from what the customer says, not from the event.

The version pin

The playbook is part of the document, so it's copied into the T25 version row at publish. A journey that started on script v3 keeps saying v3. A wording fix that should reach open runs goes out with migrate. Both behaviours already exist.

Size

Fifty lines of Hindi at ~200 chars is ~10KB in the document, copied per publish. Canon: T25 is "tens of versions, not millions of rows." The rendered walk is ~3KB in a jsonb lead payload. Neither is a number worth designing around.

Sharing lines across plans

Not now. If the same Fibe walk is needed by three plans, the honest move is to promote lines to a merchant-owned store and let plans reference it — a later ruling with its own table. Starting there would be building the store before the second plan exists.

The console

Loom needs a playbook editor: a lines list and blocks with when rows. Same gap it already has for window and match; the shape is a form, not a canvas.

What this buys, in one line

One agent, edited only for behaviour. Every word it says for every lender at every stage, chosen by the plan from the event and handed over finished — and the same chosen words reach WhatsApp and webhooks without any node learning anything.

"""The playbook (modules/05 §The playbook) — PURE. The laws at publish, the pick and the
render at fire time. Text lives in `lines` once; a block names lines and never holds
text; the last row of every block has no `when`."""

HOLE = re.compile(r"\{([A-Za-z_][A-Za-z0-9_]*)\}")


def laws(definition: WorkflowDefinition, catalogs: Catalogs) -> List[str]:
    pb = definition.playbook
    if pb is None:
        return []
    problems: List[str] = []
    node_ids = [n.id for n in definition.nodes]
    declared = declared_fact_names(definition, catalogs)   # the send-variables RHS law, reused
    for name, rows in pb.blocks.items():
        if not rows or rows[-1].when:
            problems.append(f"playbook block {name!r}: the last row must have no `when` — it is the default")
        for row in rows:
            for field in predicates.fields_named_in(row.when):
                problems.extend(f"playbook block {name!r}: {p}" for p in predicates.field_problems(field, node_ids))
            for line in _names(row.say):
                if line not in pb.lines:
                    problems.append(f"playbook block {name!r}: {line!r} is not in lines")
    for line, text in pb.lines.items():
        if "\n" in text or "\r" in text:
            problems.append(f"playbook line {line!r} carries a line break — one line is one line")
        for hole in HOLE.findall(text):
            if hole not in declared:
                problems.append(f"playbook line {line!r}: {{{hole}}} is not a declared fact")
    return problems


def list_blocks(definition: WorkflowDefinition) -> Set[str]:
    """Blocks whose `say` is a list anywhere — many lines, so never a WhatsApp blank."""
    pb = definition.playbook
    return {n for n, rows in (pb.blocks.items() if pb else []) if any(isinstance(r.say, list) for r in rows)}


def resolve(definition, facts, stage_facts, customer) -> Dict[str, str]:
    """PURE: every block rendered, {block: text}. Raises NodeParked naming a leftover hole."""
    pb = definition.playbook
    if pb is None:
        return {}
    out: Dict[str, str] = {}
    for name, rows in pb.blocks.items():
        row = next(r for r in rows if matches(r.when, lambda p: predicates.lookup(p, facts, stage_facts, customer)))
        names = _names(row.say)
        rendered = [_fill(pb.lines[n], facts, n) for n in names]
        out[name] = rendered[0] if isinstance(row.say, str) else "\n".join(f'- {n}: "{t}"' for n, t in zip(names, rendered))
    return out


def _fill(text: str, facts: Dict[str, Any], line: str) -> str:
    def one(m: re.Match) -> str:
        v = facts.get(m.group(1))
        if v is None or isinstance(v, bool) or not isinstance(v, (str, int, float)):
            raise NodeParked(f"playbook line {line!r}: {{{m.group(1)}}} has no value on this run")
        return str(v)
    return HOLE.sub(one, text)
